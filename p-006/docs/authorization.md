# Server authorization

`policy/opa/authz.rego` is the real Rego v1 policy; default false. The PEP supplies only validated
subject/tenant/roles, requested resource tenant/model/action, fixed provider/classification/client,
active state and quota context. Policy data is a reviewed projection of `config/hardened.json`.
Ordinary users: local-basic; platform admin: also local-admin. Tenant-admin operation requires its
role and own tenant. Platform operation requires platform-admin and platform tenant. No cross-tenant
platform bypass is implied. Unknown users, roles, model IDs, provider routes and policy versions deny.

Policy and decision caching are absent. Each call is request-bound before Vault or LiteLLM access.
Missing/invalid policy responses, outage and timeout deny. Decision IDs are generated by the PEP,
not represented as OPA server-issued IDs. The audit event records version and reason. A stale caller
body cannot change the forwarded model or identity because the PEP reconstructs the request.
The gateway HMAC binds the entire reconstructed body, timestamp and single-use nonce.

`policy/opa/authz_test.rego` runs in the actual OPA binary. Python enforcement fixtures test that
adapter denial prevents downstream calls; only live requests establish native policy integration.
