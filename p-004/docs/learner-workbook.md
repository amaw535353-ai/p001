# Independent learner workbook — no answer key

All work must stay within authorized synthetic local scope. Do not copy the
generated diagram or use AI-generated steps as independent competency evidence.

| Gate | Status | Independent evidence | Human reviewer |
|---|---|---|---|
| G1 architecture understanding | NOT DEMONSTRATED | | |
| G2 independent reproduction | NOT DEMONSTRATED | | |
| G3 unfamiliar architecture | NOT DEMONSTRATED | | |
| G4 consultancy communication | NOT DEMONSTRATED | | |

1. Reconstruct a synthetic system architecture from source and, where authorized,
   independently observed requests. Which exact claims cannot be established?
2. Distinguish user/tenant browser identity, backend workload identity and service
   principal. Which security decisions were not observed?
3. Identify at least five candidate trust boundaries applicable to your target,
   considering network, tenant, connector, model, agent and telemetry paths. What
   evidence would confirm each crossing and the relevant control behavior?
4. Compare a valid in-scope endpoint inventory with its declared API contract.
   Which rejected targets, unobserved flows and blind spots limit your conclusion?
5. Design and carry out an additional authorized read-only observation or offline
   inspection beyond this suite. Record its hypotheses, method and limitations.
6. Inspect an unfamiliar or modified local application without AI step-by-step
   guidance. Explain its graph differences and alternate interpretations.
7. Write a defensible consultancy scoping memo/threat-model input, stating unknown
   coverage and the independent work still required before any finding.
8. Review a genuine scanner-originated candidate when one is available. Why is the
   alert not automatically a confirmed vulnerability? Do not invent a scan result.
