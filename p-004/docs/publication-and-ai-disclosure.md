# Publication, attribution and AI disclosure

Codex generated and revised this implementation, documentation and engineering
tests with human-provided requirements. AI assistance is not independent security
validation, legal review, human proficiency, or proof of control effectiveness.
The lab is fictional and synthetic; accidental resemblance is not anonymity.

Before publishing, a human must:

- Review the diff, generated evidence and scope/status claims. Do not publish
  real source, proprietary names, credentials, raw response bodies, HARs, auth
  state, review stores, screenshots, Docker/cluster state or unreviewed artifacts.
- Keep reports, evidence, caches and `.runtime/` ignored; share only deliberately
  reviewed synthetic projections. No upstream push/publication is automatic.
- Review `dependency-inventory.json` and the distributions' LICENSE files. Python
  dependencies have their own licenses; package use does not relicense their code.
  No repository-wide license was assumed or added. Obtain owner/legal approval
  before choosing a distribution license.
- Attribute P-001/P-002/P-003 source reused through explicit local interfaces.
  P-003's separately pinned framework content retains its existing attribution;
  P-004 defines proposed internal checks and copies no OWASP requirement text.
- Onyx/OpenHands/ZAP/Playwright names and prompt tool numbers identify optional
  mappings, not endorsement, installed vendor editions or verified compliance.
- Preserve exact limitations, real test counts, optional skips and G1–G4 NOT
  DEMONSTRATED. Never transform candidates into confirmed client findings.

The four named crosswalk/roadmap documents were searched but unavailable. Their
detailed mappings have not been inferred. Dependency versions/hashes come from
actual installed distributions and the lock reused from the inspected foundation.
