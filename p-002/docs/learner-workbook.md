# Independent learner workbook

SYNTHETIC — TRAINING DATA — NOT A REAL CLIENT

| Gate | Evidence to supply independently | Status | Human verifier |
|---|---|---|---|
| G1 Guided understanding | Explain schema, roles, ownership, classification, provenance and boundaries from code and fixtures | NOT DEMONSTRATED | |
| G2 Independent reproduction | Reproduce clean generation; independently verify allow/deny per key boundary and explain evidence | NOT DEMONSTRATED | |
| G3 Unfamiliar implementation | Infer relationships and inconsistencies from a hidden/modified fixture or unfamiliar adapter | NOT DEMONSTRATED | |
| G4 Consultancy delivery | Scope, validate a real weakness if present, assess impact/fix, retest and defend a report | NOT DEMONSTRATED | |

1. What evidence distinguishes a generated human identity from an authenticated caller?
2. How would you establish that a tenant boundary was tested through an ordinary account?
3. Which relationships must remain valid after a membership change, and at what time?
4. How would you detect a cross-tenant join without assuming it is unauthorized sharing?
5. How would you compare a canonical source with a differently timed retrieval export?
6. What does a label's provenance tell you, and what does it not tell you about access?
7. What must remain bound between a request, approval and later action?
8. How would you challenge the reference oracle rather than treating it as ground truth?
9. Which platform behavior would you remeasure when adapting to an unfamiliar edition?
10. How would you distinguish a stale fixture, a test setup failure and a confirmed weakness?

For each challenge, leave your hypothesis, method, evidence, uncertainty, conclusion,
remediation and retest notes blank until you perform the work. These prompts are not
location-based hints or exploit instructions. A second AI review may critique the
reasoning but cannot demonstrate independent human competence.
